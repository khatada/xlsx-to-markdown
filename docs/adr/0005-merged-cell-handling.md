# ADR-0005: マージセルはマスターセルにコンテンツを保持し子セルを空にする

## ステータス

差し替え済み (by [ADR-0008](0008-html-table-format.md))

## コンテキスト

Excel のセル結合（マージセル）は、複数のセルを1つに見せる機能である。SheetJS では `ws['!merges']` にマージ範囲のリストが格納され、マスターセル（左上端）のみが値を持つ。

Markdown テーブルには colspan/rowspan の概念がない（GFM の制約）。マージセルをどのように扱うかを決める必要がある。

検討した選択肢：

### A. マスターセルにコンテンツ、子セルは空（採用案）

```
| 年度 | Q1  | Q2  |
| ---- | --- | --- |
| 2024 | 100 | 200 |
|      |     |     |   ← 縦マージの子セル
```

- メリット: シンプル。情報の欠損はない（マスターセルに値が残る）
- デメリット: テーブルの視覚的構造が元の Excel と異なる

### B. マスターセルの値を全子セルに複製（コンテンツ展開）

```
| 年度 | Q1  | Q2  |
| ---- | --- | --- |
| 2024 | 100 | 200 |
| 2024 |     |     |   ← 縦マージ → 値を複製
```

- メリット: データとして解釈しやすい（CSVに近い）
- デメリット: 元のセル結合の意図（「この行はQ1〜Q4全体の見出し」など）が失われる

### C. HTML テーブルで colspan/rowspan を表現

- メリット: 完全な構造を保持
- デメリット: [ADR-0003](0003-markdown-table-format.md) で GFM テーブルを選択しているため一貫性が失われる

## 決定

**A. マスターセルにコンテンツを保持し、子セルは空にする**を採用する。

理由：

1. GFM テーブルで colspan/rowspan を表現する標準的な方法がない
2. 情報の完全性はマスターセルが保持しているため損なわれない
3. 実装がシンプル（SheetJS の `!merges` を使って子セルアドレスのセットを構築するだけ）

マージセルの判定ロジック：

```
mergedChildSet = {
  全マージ範囲の (s.r, s.c) 以外の全セルアドレス
}
```

レンダリング時に `mergedChildSet` に含まれるアドレスのセルは値を空文字として扱う。

## 結果

- 縦方向のマージ（行結合）では下の行に空セルが現れる
- 横方向のマージ（列結合）では右のセルが空になる
- テーブルヘッダーでよく使われる「見出しスパン」（例: Q1〜Q2 をまとめた「上半期」列）は空セルとして表現されるため、元の意図が伝わりにくい場合がある。この制約はドキュメントに明記する
